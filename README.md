# LaTeXFlow

A local-first, real-time **bidirectional document ↔ LaTeX editor**. Write in a
Google Docs–style rich-text editor and watch it become LaTeX, or write raw
LaTeX and watch the rich document update — both directions go through a
structured internal document model, not string-to-string regex hacks.

```
Rich Editor (Tiptap)  ──┐                      ┌── LaTeX Parser
                         ├──► Document Model ◄──┤
LaTeX Editor (Monaco)  ──┘                      └── LaTeX Generator
```

## Features

- **Dual-mode sync** — `Document → LaTeX`, `LaTeX → Document`, or `Dual`
  (both directions live), with visible sync status (`● Synced` /
  `● Updating…` / `⚠ Conversion issue`) and loop-safe debounced conversion.
- **Rich document editor** (Tiptap/ProseMirror) — headings, bold/italic/
  underline/strike/code/sub/superscript, text color & highlight, alignment,
  bullet/ordered/task lists (with nesting), blockquotes, code blocks, tables,
  images, links, horizontal rules, page breaks.
- **Inline & block equations** rendered live with KaTeX, click-to-edit in
  place; block equations support numbered `equation` / `align` / `gather`
  environments with labels.
- **LaTeX editor** (Monaco) — custom LaTeX syntax highlighting, bracket
  matching, autocomplete for common commands, inline diagnostics with
  click-to-jump.
- **Diagnostics panel** — parse errors/warnings from the LaTeX side, never
  crashes the app; unrecognized LaTeX is preserved verbatim, never deleted.
- **Preamble panel** — edit `\documentclass`, packages, and extra preamble
  commands independently of document content.
- **Layouts** — split, stacked, document-only, LaTeX-only, plus an optional
  rendered preview pane; resizable divider; remembered across reloads.
- **Command palette** (`Ctrl/Cmd+Shift+P`), keyboard shortcuts, File/Edit/
  Insert/Format/View/Help menu bar.
- **Local-first storage** — autosaved to IndexedDB, a document sidebar
  (create/rename/duplicate/delete/search), no server, nothing leaves the
  browser.
- **Import/export** — `.tex`/`.md`/`.txt` import, export to `.tex`, `.md`,
  `.html`, `.txt`, and PDF via the browser's print dialog.
- **Light/dark themes**, responsive layout (tabs on mobile).

## Architecture

```
src/
├── components/        UI: AppShell, TopBar, MenuBar, Toolbar, DocumentEditor,
│                       LatexEditor, PreviewPanel, FileSidebar, StatusBar,
│                       CommandPalette, SettingsModal, Diagnostics, ui/*
├── editor/             Tiptap extension list + custom nodes (math, page
│                       break, unsupported-LaTeX placeholder) + command registry
├── conversion/         documentModel types, documentToLatex, latexParser,
│                       tiptapBridge (Tiptap JSON ↔ DocumentModel), escaping
├── hooks/               useSyncEngine (loop-safe bidirectional sync),
│                       useAutosave, useKeyboardShortcuts, useDocumentActions
├── storage/             IndexedDB (via `idb`)
├── state/               Zustand stores: document, sync, settings (persisted), ui
├── utils/               Monaco LaTeX language, export/import helpers
├── sample/              The BME "Research Notes" sample document
└── types/document.ts    The DocumentModel IR shared by both editors
```

**Why a document model?** Direct rich-text-HTML ⇄ LaTeX-string conversion
degrades over repeated edits. Both editors instead read/write a plain
TypeScript `DocumentModel` (paragraphs, headings, lists, tables, equations,
etc.); `documentToLatex` and `latexParser` are the only things that know
LaTeX syntax, and `tiptapBridge` is the only thing that knows Tiptap's JSON
shape.

**Loop prevention** (`useSyncEngine`): a document edit converts to LaTeX and
writes it into the Monaco editor's controlled `value`; the resulting `onChange`
is swallowed by a one-shot suppress flag. A LaTeX edit converts to a document
model and calls `editor.commands.setContent(json, { emitUpdate: false })`, so
Tiptap never fires its own `onUpdate` for that write — no flag needed on that
side because the event is suppressed at the source. Both directions also
debounce (default 200ms, configurable in Settings) and track `origin` so the
status bar can show `Updating…` mid-conversion.

## Supported LaTeX (v1)

Round-trips reliably for content generated by this app; also parses typical
hand-written LaTeX using this subset:

```
\section \subsection \subsubsection \paragraph
\textbf \textit \emph \underline \sout \texttt
\textsubscript \textsuperscript \href
\textcolor[HTML]{...} \colorbox[HTML]{...}  (also plain \textcolor{red}{...};
    \hl{...} still parses for backward compatibility but is no longer generated)
\begin{itemize} \begin{enumerate} \item  (one level of nesting, plus a
    \item [$\boxtimes$]/[$\square$] task-checkbox convention)
\begin{quote}
\begin{verbatim} \begin{lstlisting}
\[ ... \]   \( ... \)   $...$
\begin{equation} \begin{align} \begin{gather}  (with \label)
\begin{table} \begin{tabular} \begin{tabularx} \begin{longtable}
    \caption \hline \toprule \midrule \bottomrule \rowcolor{...}
    (tabularx/longtable work both wrapped in \begin{table} and bare;
    longtable's \endfirsthead/\endhead repeated-header markers are
    resolved to a single header row)
\begin{figure} \includegraphics \caption
\begin{thebibliography} \bibitem  (mapped to a numbered reference list)
\hrulefill   \newpage \pagebreak \clearpage
\documentclass \usepackage \title \author \maketitle
```

Structural/typographic commands with no visible output of their own —
`\phantomsection`, `\addcontentsline`, `\tableofcontents`, `\listoffigures`,
`\listoftables`, `\appendix`, `\pagenumbering`, `\hypersetup`, `\setcounter`,
`\(re)newcommand`, `\setstretch`, `\setlength`, `\vspace`, `\hspace`, bare
font-size/alignment declarations (`\centering`, `\small`, `\Large`, ...) —
are recognized and dropped rather than leaking into the document as literal
text. Custom macros you've defined yourself (e.g. a `\placeholder{...}`
helper) aren't expanded — since we don't execute your preamble — but their
arguments are preserved as visible literal text, never silently discarded.

Block splitting isn't blank-line-based: hand-written LaTeX routinely packs
`\section`, `\subsection`, and `\begin{table}` back-to-back with no blank
lines between them at all, so each is still recognized as its own block
rather than being swallowed into one opaque chunk with everything after it.

`\usepackage{xcolor}` (for `\textcolor`/`\colorbox`) and `\usepackage{ulem}`
(for `\sout`) are injected into the exported preamble automatically whenever
the document actually uses color, highlight, or strikethrough — you don't
need to add them by hand, and documents saved before this was added will
pick them up the next time they're exported or synced.

**Unsupported LaTeX is never silently dropped.** A block-level construct the
parser doesn't recognize (an unknown environment, a malformed block) is
preserved as a read-only "Unsupported LaTeX construct" block holding the
original raw source — editing it happens on the LaTeX side, not the document
side. An unrecognized *inline* command is preserved as literal text rather
than styled specially.

## Limitations

- Footnotes, citations (`\cite`), and cross-references (`\ref`/`\label`
  outside equations) are not modeled as first-class document nodes — they
  pass through as literal text, not a dedicated UI element.
  `\begin{thebibliography}` is the one exception: it's mapped to a numbered
  list since that's a reasonably close semantic match.
- `\multicolumn{n}{spec}{content}` table cells aren't given real colspan —
  the cell's content (including any formatting inside it) is preserved, but
  it renders as one normal cell with the `\multicolumn{...}{...}{` wrapper
  visible as literal text rather than actually spanning columns.
- The Markdown importer/exporter covers headings, bold/italic, lists, code
  fences, blockquotes, `$$`/`$` math, and tables — not full CommonMark.
- PDF export is the browser's print dialog, not a real LaTeX compile. Full
  `.tex` → PDF compilation needs a server-side engine (Tectonic, TeX Live) and
  is intentionally out of scope for this local-first v1.
- `.docx` import is not implemented (no bundled browser-compatible parser).
- Document-side "Find" relies on the browser's native page search; the
  LaTeX editor has Monaco's built-in find/replace (`Ctrl/Cmd+F`).
- The LaTeX parser is a defined, documented subset (above), not a general
  TeX engine — arbitrary hand-written LaTeX with unusual macros will surface
  as an "Unsupported LaTeX construct" block rather than being interpreted.

## GitHub Pages deployment

`.github/workflows/deploy.yml` builds and deploys `dist/` on every push to
`main`. GitHub Pages serves project sites from `/<repo-name>/`, so the Vite
`base` path must match — set it once via a repository variable:

1. In your GitHub repo: **Settings → Secrets and variables → Actions →
   Variables** → add `VITE_BASE_PATH` = `/<your-repo-name>/`.
2. **Settings → Pages** → set **Source** to **GitHub Actions**.
3. Push to `main`.

If `VITE_BASE_PATH` isn't set, the workflow falls back to
`/<repo-name>/` automatically using the repository's own name, so it works
out of the box for a normal project site without editing any file. For a
user/org site (`https://<user>.github.io/`), set `VITE_BASE_PATH` to `/`.
